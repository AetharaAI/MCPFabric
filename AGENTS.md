# AGENTS.md

## Role
This repository is the MCPFabric frontend.

Primary agent responsibility on this VM:
- keep `mcpfabric.space` usable as the operator/admin surface for Fabric
- expose live backend capabilities already present in Fabric-A2A before changing backend behavior
- preserve production safety: validate against live contracts, avoid speculative API changes, and prefer thin vertical slices

This frontend was originally generated by Manus AI and is now being converted into a production operator UI by Codex.

## Environment
- Frontend repo root: `/home/ubuntu/mcp-fabric-site/MCPFabric`
- Live site: `https://mcpfabric.space`
- Live nginx web root: `/var/www/mcpfabric`
- Local dist output: `/home/ubuntu/mcp-fabric-site/MCPFabric/dist`
- Backend API origin currently used by the frontend: `https://fabric.perceptor.us`

## Current Mission
Turn MCPFabric from a mostly mock/demo frontend into a real admin and operator console for:
- admin key verification
- API key creation, listing, revoke, and scoped operator bootstrap
- live MCP tool calls
- live A2A message send / queue inspection
- Passport OIDC sign-in via the Syndicate realm
- eventually full async stream observability

## Working Rules
- Frontend changes come first unless the frontend exposes a genuine backend mismatch.
- Do not change backend behavior just to compensate for a frontend assumption.
- Use the live OpenAPI, smoke tests, and direct curl validation before changing contracts.
- Keep production deploys reversible and obvious.
- Do not commit secrets into repo docs.
- Treat `.env` values as runtime bootstrap inputs, not documentation content.

## Known Production Facts
- `mcpfabric.space` is served by host nginx from `/var/www/mcpfabric`
- `fabric.perceptor.us` is the live backend origin
- admin verify works
- production key creation works
- client key verify works
- `/mcp/call` works with plain payloads of the form `{ "name": ..., "arguments": ... }`
- `fabric.message.send` works
- `fabric.message.queue_status` works
- browser CORS/preflight between frontend and backend is fixed

## Current Frontend Gaps
- `Observatory` is still mock-driven
- `Registry` still leans on mock catalog data
- SSE/live async stream visualization is not yet wired to the real backend
- backend-side Passport identity enforcement for Fabric admin APIs is not yet wired

## Standard Frontend Workflow On This VM
1. Inspect live contract and smoke-test notes.
2. Patch frontend in this repo.
3. Build with `npm run build`.
4. Publish to live web root with `sudo rsync -a --delete dist/ /var/www/mcpfabric/`.
5. Verify `https://mcpfabric.space` serves the new bundle names.

## Coordination Notes
- Backend repo is separate: `/home/ubuntu/fabric/mcp-modular/Fabric-A2A`
- Backend was originally built/sharpened by Codex.
- Frontend must track backend reality, not frontend fiction.
- If an issue reproduces only in browser and not in curl, check CORS/preflight before questioning auth.
- For Passport auth, the frontend must talk only to Passport and must not integrate Hugging Face directly.
- Do not expose Passport client secrets in the browser bundle; use public-client PKCE in the SPA.
- Guest browsing remains open by default.
- Passport sign-in currently gates API key workflows in the frontend.
